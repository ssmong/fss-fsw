# 003. fss_hal — 하드웨어 추상화 계층

**패키지 유형:** `ament_cmake` (C++17)

PLC·IMU·Vicon·반응휠의 장치 처리를 ROS와 분리된 C++ 계약으로 제공한다.
중복 Python HAL은 제거했으며, Python 보정 수학은 `fss_sensors.imu_transform`에 남긴다.

## 구성

| 헤더 (`include/fss_hal/`) | 역할 |
|---|---|
| `valve_hal.hpp` | `ValveHal` 밸브 계약과 `SimHal` |
| `plc_hal.hpp` | libmodbus 기반 `PlcHal`, 오류 주입용 transport 계약 |
| `imu_hal.hpp` | IMU 표본·장착 회전·공분산·유효성 검사 |
| `pose_sensor.hpp` | 평면 포즈 센서 계약 |
| `vicon_hal.hpp` | 지상국 UDP JSON 수신·검증 |
| `reaction_wheel.hpp` | USB-CDC 반응휠 및 모의 구현 |

## 밸브 HAL

`ValveHal`은 `connect()`, `disconnect()`, `set_valves()`, `set_main_valve()`,
`emergency_stop()`, `is_connected()`, `last_rtt_ms()`를 제공한다.
밸브 드라이버가 `use_sim`에 따라 `SimHal` 또는 `PlcHal`을 생성한다.
두 구현 모두 연결 시 출력을 0으로 초기화하고 종료 시 비상정지를 시도한다.

### PLC 연결과 레지스터

기본 연결은 `192.168.1.2:502`, timeout 1초, Modbus Unit ID 1이다.
설정은 `config/hardware/plc.yaml`에서 전달한다.

| 레지스터 | Modbus 주소 | 용도 |
|---|---|---|
| D00099 | 99 | 메인 밸브·PLC watchdog heartbeat |
| D00100–D00107 | 100–107 | 8개 비례밸브 |

`set_valves()`는 정규화 입력을 `int(input * 4000)`으로 변환하고 FC16으로 일괄 전송한다.
4000은 XBF-DC04A 출력 범위이며 4095가 아니다. Modbus 연산은 mutex로 직렬화한다.
`last_rtt_ms()`는 마지막 밸브 쓰기 왕복 시간을 제공하지만, 지연 상한을 보장하지 않는다.
`read_digital_inputs()`는 읽기 실패 시 비어 있는 `std::optional`을 반환한다.
통신 실패는 fault로 유지하며 자동 재연결하지 않는다. 비상정지는 비례밸브와 메인밸브
두 출력을 각각 정지 시도하므로 한쪽 실패가 다른 쪽 시도를 막지 않는다.

`SimHal`은 같은 0–4000 정수 변환과 메인밸브 상태를 메모리에 보관한다.
Python 플랜트는 HAL을 직접 import하지 않고, C++ 드라이버가 전송 성공 후 발행한
`/actuators/valve_commands`를 구독한다.

## 센서 HAL

외부 Xsens 드라이버가 USB 수신을 맡으며 C++ `XsensImuHAL`은 입력 표본의 장착 회전,
공분산 회전, 자세 변환과 유효성 검사를 수행한다. rad/s·m/s² 단위, xyzw 자세,
원본 측정 시각과 미제공 공분산 표식(-1)을 보존한다. 비유한 값·잘못된 quaternion은
예외로 보고하고 브릿지가 표본을 폐기한다. 포화는 경고한다.

`ViconHAL`은 FSS_VICON UDP JSON을 비차단 수신해 선택한 물체의 x/y를 mm→m,
yaw를 deg→rad로 변환한다. 잘못된 데이터, 중복·역순 프레임, 추적 실패를 폐기한다.
수신 처리량을 제한하고 최신 프레임을 선택한다. ROS 브릿지가 추가 좌표 변환,
송신 시각 기준 속도 차분과 수신 시각 stamping을 담당한다.
상세 패킷·프레임 규약은 [센서 문서](005_Sensors.md)를 따른다.

## 반응휠 HAL

`ReactionWheelHal`의 연결·토크·상태·정지 계약을 `SerialReactionWheelHal`과
`SimReactionWheelHal`이 구현한다. 명령은 휠 축 토크 [N·m]이며 USB 구현은 SAMD21의
`T,...`, `S,...`, `ACK,...`, `FAULT,...` 프레임을 처리한다.
부분 프레임, 입출력 대기와 버퍼 크기를 제한하며 FAULT는 STOP 뒤 새 STOP telemetry로
해제한다. 모의 구현은 휠 회전속도나 플랜트 동역학을 모델링하지 않는다.
[토픽·서비스·실행법](004_Actuators.md#반응휠-samd21)을 참고한다.

## 의존성과 검증

libmodbus, nlohmann/json, yaml-cpp와 POSIX socket/termios를 사용한다.
검사는 native 단위 테스트, 오류 주입, 실제 localhost TCP/UDP와 pseudo-terminal 통신을
사용한다. 실제 PLC·센서·반응휠의 장치 동작과 Jetson 통신 지연은 별도 검증 대상이다.
