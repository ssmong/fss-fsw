# 006. fss_arm — 로봇팔 드라이버

**상태: 모의 환경 검증**
**패키지 유형:** `ament_python` (`fss_arm`), `ament_cmake` (`fss_arm_msgs`)

## 개요

에어베어링 테스트베드에 장착하는 3축 Dynamixel 로봇팔의 ROS2 제어 인터페이스다.
외부 제어 프로그램에서 관절 위치·속도·전류 명령을 받아 장치로 전송하고 측정 상태를 발행한다.
관절 순서는 `[shoulder, elbow, wrist]`이며 현재 제어표는 XM430-W350 3개를 지원한다.

## 구성

| 파일 | 역할 |
|---|---|
| `arm_driver_node.py` | ROS 명령·서비스, 시스템 모드 연동, 제어주기 및 fault 관리 |
| `commands.py` | 위치·속도·전류 단위 변환, 관절 매핑, 명령 한계와 수명 검사 |
| `dynamixel_bus.py` | SDK 통신, 장치 설정, 상태 읽기, 목표 쓰기, 토크 제어 |
| `fss_arm_msgs/msg/JointCurrent.msg` | 관절 방향 기준 모터 전류 A |
| `fss_arm_msgs/srv/SetCommandMode.srv` | 위치·속도·전류 제어 모드 선택 |

## ROS2 인터페이스

| 유형 | 이름 | 타입 | 설명 |
|---|---|---|---|
| 구독 | `/system/mode` | `fss_interfaces/SystemMode` | ACTIVE 상태 및 heartbeat |
| 구독 | `/arm/velocity_command` | `sensor_msgs/JointState` | velocity 3개, rad/s; position/effort 비움 |
| 구독 | `/arm/position_command` | `sensor_msgs/JointState` | position 3개, rad; velocity/effort 비움 |
| 구독 | `/arm/current_command` | `fss_arm_msgs/JointCurrent` | current 3개, A |
| 발행 | `/arm/joint_states` | `sensor_msgs/JointState` | 측정 관절각 rad 및 속도 rad/s |
| 발행 | `/arm/currents` | `fss_arm_msgs/JointCurrent` | 측정 모터 전류 A |
| 발행 | `/arm/status` | `std_msgs/String` | dry_run, 선택 모드, enable, fault |
| 발행 | `/arm/timing` | `std_msgs/String` | 실행 주기 통계 JSON, 1 Hz |
| 서비스 | `/arm/set_enabled` | `std_srvs/SetBool` | 시작 또는 정지·fault 해제 |
| 서비스 | `/arm/set_command_mode` | `fss_arm_msgs/SetCommandMode` | disable 상태에서 모드 선택 |

명령은 최신 timestamp를 포함해 기본 100 Hz로 발행한다. 같은 위치를 유지할 때도 계속 발행한다.
위치는 보정된 관절 좌표계의 목표각이며, 전류는 관절 +방향 기준 모터 전류다.
전류를 토크로 환산하지 않으며 `JointState.effort`는 비워 둔다.

## 설정

설정 파일은 `config/hardware/arm.yaml`이다. 현재 값은 모의 실행 예제이며 장치 사양값이 아니다.

| 설정 | 의미 |
|---|---|
| `dry_run`, `hardware_confirmed` | 모의 실행 여부 및 실제 장치 매핑 확인 |
| `port`, `baudrate`, `model_numbers`, `ids` | 직렬 포트·통신 속도·모터 모델·ID |
| `directions`, `gear_ratios`, `zero_ticks` | 회전 부호·출력축/관절 감속비·영점 |
| `lower_limits`, `upper_limits` | 관절 위치 한계, rad |
| `velocity_limits`, `current_limits_a` | 관절 속도 및 모터 전류 명령 한계 |
| `position_profile_velocity`, `position_profile_acceleration` | 위치 모드 내부 profile 속도·가속도 |
| `acceleration_limits` | 위치 profile 가속도 상한, rad/s² |
| `initial_position_rad` | 모의 실행 초기 관절각; 실제 장치의 이동 목표가 아님 |
| `control_rate_hz` | 명령 처리 주기, 기본 100 Hz |
| `command_timeout_s`, `mode_timeout_s` | 명령 만료 0.1초, ACTIVE heartbeat 만료 1.5초 |
| `bus_watchdog_s`, `return_delay_us` | 장치 watchdog 및 응답 지연 |

시작 설정은 read-only다. 실행 중 명령 모드는 서비스로 전환한다.
실제 장치를 사용할 때는 포트·매핑·각 한계를 확인하고 `dry_run: false`,
`hardware_confirmed: true`를 적용한다. 모터 토크 OFF, Drive Mode(10)=0,
Status Return Level(68)=2, Hardware Error Status(70)=0, Bus Watchdog(98)=0 상태에서 연결한다.

## 단위 변환과 통신

영점·방향·감속비는 관절과 모터 출력축 사이에 적용한다.

```text
joint_position = direction × (raw_position - zero_ticks) × (2π / 4096) / gear_ratio
raw_velocity = round(direction × gear_ratio × joint_rad_s / (0.229 × 2π / 60))
raw_current = round(direction × motor_current_a / 0.00269)
```

양자화로 설정 한계를 넘지 않도록 표현 가능한 내부 값으로 제한한다.
전류에는 외부 감속비를 곱하지 않는다. 위치는 다회전 모드이며 ±π로 wrap하지 않는다.

선택 모드의 목표는 3축 SyncWrite 한 번으로 전송한다. 상태는
SyncRead 요청 1개와 모터 응답 3개로 읽는다. Indirect Address 1–23(168–212)에 아래 주소를
배치하고 Indirect Data 1–23(224–246)를 읽는다.

| 블록 offset | 원래 주소 | 항목 |
|---|---|---|
| 0 | 70 | Hardware Error Status |
| 1 | 98 | Bus Watchdog |
| 2 | 64 | Torque Enable |
| 3–6 | 128–131 | Present Velocity |
| 7–10 | 132–135 | Present Position |
| 11–14 | 104–107 | Goal Velocity |
| 15–16 | 126–127 | Present Current |
| 17–18 | 102–103 | Goal Current |
| 19–22 | 116–119 | Goal Position |

연결 시 응답 지연과 indirect 매핑을 기록·확인한다. EEPROM 값은 차이가 있을 때만 쓴다.
같은 직렬 포트와 indirect 영역은 한 드라이버가 사용해야 한다.
SDK의 CRC·byte stuffing 처리 뒤 응답 길이·ID·오류와 직전 목표 반영을 검사한다.
모터 응답은 순차 수신이며 관절별 측정 시각이 동일하다는 보장은 아니다.

## 시작·정지 및 오류 처리

enable은 최신 ACTIVE 상태와 정지한 관절을 요구한다. 위치 모드는 현재 측정각을,
속도·전류 모드는 0 목표를 모터별로 확인한 뒤 토크를 켠다.
모드 전환 시 게인을 보존하고 위치 카운터의 연속성을 검사한다.

명령 만료, ACTIVE 이탈·만료, 잘못된 입력, 위치 한계, 통신·장치 오류는 fault로 정지한다.
속도·전류 정지는 0 목표 후 torque OFF, 위치 정지는 torque OFF다.
토크 해제는 자세 유지나 물리적인 즉시 정지 보장이 아니다.
정지 통신 실패 시 fault 상태에서는 추가 읽기로 장치 watchdog을 연장하지 않는다.

fault는 정지에 성공한 `set_enabled false` 요청으로 해제한다. 자동 재시작하지 않는다.
속도 스트리밍에 가속도 제한이나 목표-측정 추종 오차 감시는 적용하지 않는다.
전류 모드는 측정 속도 한계와 timeout 동안의 예상 위치도 검사한다.

## 제어주기 확인

`/arm/timing`은 enabled 상태에서 시작한 주기의 실행 시간을 기록한다.

- `target_period_ms`: 기본 10 ms.
- `last_*_ms`, `max_*_ms`: 콜백 간격, read, write, 전체 cycle 시간.
- `cycle_overruns`: 실행 시간이 목표 주기를 초과한 횟수.
- `late_intervals`: 콜백 간격이 목표 주기의 1.5배를 초과한 횟수.

1 Mbps의 기본 패킷 기준 읽기+쓰기는 위치·속도 모드 148 byte(약 1.48 ms),
전류 모드 142 byte(약 1.42 ms)다. 모터 처리, USB 지연, byte stuffing 및 호스트 실행 시간은
별도이며 실제 100 Hz 달성 여부는 장치에서 측정해야 한다.

## 실행과 검사

```bash
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/local_setup.bash
ros2 launch fss_bringup sim.launch.py use_arm:=true use_thrusters:=false
```

dry_run의 속도는 양자화된 명령을 적분하고, 위치는 profile 속도로 제한한 이상적 이동이다.
전류는 양자화한 값을 피드백으로 표시하며 전류에 의한 운동은 생성하지 않는다.
본체와 팔의 결합 동역학은 포함하지 않는다.

검사는 `tests/arm/`의 단위·SDK 패킷·ROS 통신 테스트와
`scripts/diagnostics/arm_launch_smoke.py`의 모의 기동·종료 검사로 수행한다.
물리 모터 구동 검증은 별도다.
