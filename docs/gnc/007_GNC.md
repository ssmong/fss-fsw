# 007. fss_gnc — 유도, 제어, 할당

**상태: 완료 (Phase 6)**
**패키지 유형:** `ament_cmake` (C++17 런타임 + 선택적 Python 연구 바인딩)

## 목적

유도(Guidance), 제어(Control), 할당(Allocation)을 하나의 노드(`gnc_node`)에서 실행한다.
항법 상태를 입력받아 노즐별 목표 추력[N]을 출력하는 폐루프 제어 파이프라인.

## GNC 파이프라인

```
SpacecraftState ──▶ Guidance ──▶ TrajectoryReference ──▶ Controller ──▶ [Fx,Fy,Mz]
                                                                          │
                                                                          ▼
ThrustCommands [N] ◀── Allocator (QP) ◀── wrench [Fx, Fy, Mz]
```

## C++ 데이터 구조 (`types.hpp`)

```cpp
namespace fss::gnc {
    struct TranslationalState { double x, y, vx, vy, theta; };  // theta: 좌표 변환용
    struct TranslationalRef   { double x, y, vx, vy; };
    struct RotationalState    { double theta, omega; };
    struct RotationalRef      { double theta, omega; };
    struct TranslationalOutput { double fx, fy; };
    struct AllocatorOutput     { double duty[8]; };              // 0~1 정규화
}
```

## 유도 (Guidance)

기본 런타임은 `guidance.hpp`의 C++ `GuidanceManager`로 기준 궤적을 생성한다.
Python 연구 백엔드는 `guidance.py`를 사용한다.

| 모드 | 설명 | 설정 파일 |
|------|------|-----------|
| `target` | 단일 목표 위치/자세 유지 | `gnc/guidance/station_keep.yaml` |
| `trajectory` | 시간 기반 경유점 보간 (선형) | `gnc/guidance/trajectory.yaml` |

Python 연구 API:
- `set_target(x, y, theta)`: 고정 목표 설정
- `set_trajectory(points)`: 시간 기반 경유점 리스트 설정
- `compute(state, t) → ref`: 현재 시간의 기준 상태 반환

## 제어기 (Controller)

**병진/회전 독립 교체 가능** — C++ 추상 인터페이스 (`TranslationalController`, `RotationalController`) 기반.

### PID 제어기 (기본)

| 구성요소 | 클래스 | 설명 |
|---------|--------|------|
| 병진 | `PIDTranslational` | 2채널 (X, Y) 독립 PID |
| 회전 | `PIDRotational` | 1채널 (θ), 각도 래핑 처리 |

- **좌표계**: 오차 계산·힘 출력 모두 테이블(관성) 프레임. 테이블→본체 회전(R(θ)ᵀ)은
  `gnc_node`가 할당 직전 1회 수행 (PID/LQR 공통).
- **Anti-windup**: 적분기 클램핑 (`integral_limit`)
- **출력 제한**: `max_force`, `max_torque` — 테이블 프레임에서 클램핑.
  회전 후 본체 추력 한계와의 정합은 미해결

### LQR 제어기

| 구성요소 | 클래스 | 게인 행렬 |
|---------|--------|----------|
| 병진 | `LQRTranslational` | K: 2×4 (사전계산) |
| 회전 | `LQRRotational` | K: 1×2 (사전계산) |

- u = −K·(state − ref) (출력 클램핑; e=state−ref 부호 규약)
- K 게인은 `scripts/compute_lqr_gains.py`로 자동 계산 → `config/gnc/controller/lqr_gains.yaml`
  (`lqr.yaml`은 제어기 type 선택자일 뿐, K 데이터 아님)

## 할당기 (QP Thruster Allocator)

`QPAllocator` (C++): 원하는 wrench를 8개 노즐의 정규화 목표 추력으로 할당.

QP의 `u`는 노즐별 최대 추력으로 정규화한 목표 추력이다.
`B`의 각 열에 최대 추력을 곱하고, 할당 결과에도 같은 값을 곱해 `ThrustCommands.thrust_n` [N]으로 발행한다.
GNC는 맵에서 할당 한계인 최대 추력만 사용한다. 맵이 없으면 `vehicle.max_thrust_per_nozzle`을 사용한다.
**목표 추력→밸브 입력 역변환은 밸브 드라이버가 담당**한다. 설정은 `valve_thrust_map_file`이며
[실측 맵](../../config/calibration/valve_thrust_measured.yaml)을 참고한다.

### 추력기 구성 행렬 B (3×8)

`config/vehicle/thruster_geometry.yaml`에서 로드:

```
B * u = [Fx, Fy, Mz]ᵀ
```

### QP 정형화

```
minimize    ‖Bu - w_des‖² + λ·‖u‖²
subject to  0 ≤ u ≤ 1   (정규화 추력 범위)
```

- `λ`: `thrust_weight` (연료 절약 가중치, 기본 0.01)
- **Projected Gradient Descent**: 최대 200회 반복, 수렴 허용 오차 1e-6
- **폴백**: pseudo-inverse (B⁺ = Bᵀ(BBᵀ)⁻¹, Cramer 3×3 역행렬)

## 안전 메커니즘

- **State age 가드**: `state_age_limit_ms`(기본 100ms) 초과 미수신 → 자체 0 명령 출력.
  짧은 미수신이 회복되면 제어를 재개할 수 있으며, manager는 별도 1000ms 한계로 지속 미수신을
  감시한다. SAFE_HOLD에 진입한 뒤에는 데이터가
  회복되어도 READY → ACTIVE 요청이 필요하다. manager 감시 주기는 `control_rate_hz`와 같은 명목 주기다.
- **한계 조정**: 두 시간 한계는 동역학 기반 보장값이 아닌 임시 운용 설정이다. 실측 지연·지터·연속
  누락과 플랜트 안전 여유를 확인해 조정한다. EKF의 Vicon 입력 timeout은 별도 정책이다.
- **NaN/Inf 방어**: 밸브 명령 발행 전 유효성 검사
- **출력 클램핑**: 제어기/할당기 모두 범위 제한

## 빌드

```bash
colcon build --symlink-install --packages-up-to fss_gnc fss_actuators fss_sim
```

기본 C++ 실행에는 Python 바인딩이 필요하지 않다. 연구 백엔드를 사용할 때만
`-DFSS_GNC_BUILD_PYTHON_BINDINGS=ON`으로 빌드하고 `system.gnc_backend=python`을 선택한다.
이 경우 `_gnc_core.so`가 `fss_gnc/` 패키지 디렉토리에 설치된다.
